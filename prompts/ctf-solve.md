# ctf-solve · CTF 解题规范（Agent 瘦身版）

> 定位（原文）："本文件只规定目录、工具边界和什么时候停。解题手法自己判断，不读取别的技能。"
>
> 为什么瘦身（原文）："对于本地小模型，skills 会降低首字的速度，并误导模型严格按照 skills 的方式去执行。"

## 一、启动

1. 用户给出题目正本目录 `challenges/<分类>/CTF-xxx-<简称>/`（分类如 pwn/web/crypto/reverse/misc）。
2. 你先抽出并确认以下要素，缺的就问，不要猜：
- 题目目录（必须存在）、category、slug
- 题面原文、远程地址（含端口）、flag 格式（如 `flag{...}`）、题目已有提示
3. **一次只解一道题。** 解完按"六、完成三条件"验收后再接下一道。
4. 工作目录隔离：把题目附件**拷贝**到 `workspaces/<环境ID>/challenges/<编号>/` 再动手，原题目录保持只读、不在里面写任何文件（防污染、可回退）。（来源：摘要 §7 第 1 条）
5. 在工作目录建初始 `STATUS.md`（格式见 `STATUS-template.md`），之后所有状态只写进它，不靠记忆。

## 二、开场三板斧（零思考成本，先跑完再分析）

1. 列文件：`ls -la` 看文件名、大小；`file` 看类型。
2. 二进制跑 `strings -a -n 6`；文本文件直接搜关键词：`flag{`、`ctf{`、`FLAG{`、`key`、`password`。
3. 搜到的候选 flag 先核对：是不是题面要求的输出格式？格式不对的只是字符串，不是 flag。

（来源：摘要 §5"开场三板斧"）

## 三、工具边界

1. 只用**已经装好**的工具。比赛/解题期间**不许** `pip install` / `apt install` / `brew install`（断网环境装不了，联网环境也防污染）。
2. 本机能解的不进虚拟机/备用环境；需要重型工具（如 sage）时按登记的环境顺序走，**不要自己决定装环境**。
3. 需要人工前置动作的工具（如"先请用户打开 BurpSuite / IDA 再调 MCP"），先停下请用户打开，确认后再调，不许跳过。
4. 常用工具都没有、且用户没给替代方案 → 停下来问用户，不许自己想办法绕。

（来源：摘要 §5"工具边界"，按多环境改写）

> **场景说明**：本节是「Agent/断网/防污染」口径；人工/联网场景见 `skills/triage.md`「前置工具」（赛中缺啥装啥）。

## 四、循环铁律

1. 每轮实验前先写清：**验证哪个假设、什么结果能否定它**。没写清的不许动手。
2. 每轮只做**当前最便宜、最能把假设分开**的那一个实验；优先本地、静态、只读的手段。
3. **三种不算新事实**（来源：摘要 §5"循环铁律"原文思想）：
- 命令报错了，但报错原因没弄清；
- 同一条命令换个参数再跑一遍；
- 把工具输出原样贴进笔记，没有提炼出结论。
4. 只有提炼出"一句话新事实"才记进 `STATUS.md` 的 facts（一行一条）；失败的实验标注"已证伪"写进去，不再重跑。

## 五、停机闸门（硬规则）

**连续三轮没有新事实 → 立刻停机。**（来源：摘要 §7 第 4 条；作者称为"对模型解题能力最大的提升"，无此规则模型会"无穷无尽地解下去，甚至走向错误的方向"）

停机后只做三件事，不许多做：
1. 更新 `STATUS.md`（hypothesis 写当前卡点，next 写你认为最该试的一个实验）；
2. 按"八、汇报格式"输出未解出版；
3. **等用户给出下一步提示后再继续。** 不许自己换个思路接着试。

## 六、完成三条件（"解出"的形式化定义）

同时满足才算解出，缺一条都不算（来源：摘要 §5"完成三条件"原文）：

1. flag 字符串来自**程序输出、远程返回或题面规定的结果**（不是猜的、不是编的）；
2. 工作目录里有**一条能再次得到它的命令或脚本**（复现链超过两三步就写成 `solve.py` / `solve.sh`）；
3. 题面规定了格式时，flag 与格式一致。

## 七、防幻觉铁律

**数字、偏移、密钥、地址、flag，只写工具输出或文件里实际出现的值。**（来源：摘要 §5"防幻觉铁律"原文）

没跑过的命令不许写"结果应该是"；不确定的值标注"未验证"，不许当事实用。

## 八、汇报格式

- **解出了**：
```
flag: {{flag 字符串}}
复现: {{命令或脚本路径，一条能重跑}}
```
- **没解出**（只写这三行）：
```
卡在: {{一句话，当前卡点}}
已确认: {{已证实的事实，不超过 3 条}}
下一步: {{只写一个实验}}
```

（来源：摘要 §5"汇报格式"）

## 九、例外：按需注入

纯 LLM 知识不够时（如 CRT 泄漏密码这类冷门题型），**停下来请求用户手动把对应的 skill 文件内容贴进对话**，补完知识再解。skills 按需注入，不常驻、不预读。（来源：摘要 §5"例外"）
