# CTF 多环境模板 · 使用指南

> 这是模板仓，不是实战实例。模板仓可以公开，实战实例不可以公开。
> 模板仓里只有结构、规则、模板和脚本，没有真实 flag、没有真实题目答案、没有已登记的环境、没有日志、没有目标地址和凭据。

## 一、模板仓和实战实例要分开

| | 模板仓（公开） | 实战实例（本地，默认不公开） |
| --- | --- | --- |
| 位置 | 本仓库 | Kali 家目录 `~/CTF`，从模板复制过去 |
| 内容 | 规则、模板、脚本、格式示例 | 真实题目、认领记录、flag、过程文档、日志 |
| 能不能推公开仓 | 可以，本仓就是公开的 | 不可以，flag 和认领记录只放本地 |

实战实例的 `.gitignore` 必须挡住：解题清单、环境登记、各环境身份卡、日志、`.conflict` 副本。
模板仓里的解题清单、环境登记只是格式示例，里面只有示例行，没有真实数据。

## 二、目录结构

```
./
├── README.md                  # 本文件：使用指南
├── 协议与约束.md              # 铁律，动手前先读
├── 解题清单.md                # 格式示例：题目、分类、难度、分值、状态（含待办）、认领者、flag、平台提交、提交人、过程文档路径
├── 环境登记.md                # 格式示例：环境 ID、角色、工作目录路径、tmux 会话
├── 资源登记.md                # 本地服务、端口占用登记，避免并行环境抢端口
├── INDEX.md                   # 总索引
├── 更新日志.md                # 模板每次改动记一笔
├── challenges/                # 题目目录（共享原题，只读心态，别在里面直接改）
│   ├── README.md              # 新增题目流程
│   └── <分类>/<编号>-<简称>/题目说明.md
├── workspaces/                # 每个环境的工作目录，一环境一子目录（模板里只有说明，不含真实环境）
│   ├── README.md
│   └── <环境ID>/
│       ├── IDENTITY.md        # 身份卡
│       ├── challenges/<编号>/ # 本题的工作副本 + 过程文档.md + 解题文件
│       ├── logs/              # tmux 日志
│       └── notes.md           # 杂记（不放 flag）
├── templates/                 # 身份卡、过程文档、题目说明模板
└── scripts/                   # 建工作目录、起 tmux、查认领、带锁改状态、给窗口开日志、新增题目、查失联
├── skills/                    # 各题型解题方法沉淀（Web/Crypto/MISC/Reverse/Pwn），做题前先读
```

## 三、从模板建实战实例（只做一次）

```bash
# 把模板复制到 Kali 家目录，不要直接在模板仓里解题
cp -r ctf-multi-env-template ~/CTF
cd ~/CTF
chmod +x scripts/*.sh
```

## 四、快速开始（新环境 5 步）

1. 登记身份，建自己的工作目录：
   ```bash
   cd ~/CTF
   ./scripts/new-workspace.sh <环境ID> [主机] [角色]
   ```
   脚本会建 `workspaces/<环境ID>/`，生成 `IDENTITY.md`，并在 `环境登记.md` 里加一行。
   环境 ID 只用小写字母、数字、连字符，一环境一卡，不共用、不替别人登记。

2. 新增题目（有新题时）：`./scripts/add-challenge.sh <题名> <分类> <分值> [难度] [简称]`
   看清单，选未开始/待办的题：
   ```bash
   ./scripts/check-claim.sh <题目编号>
   ```

3. 认领：不要手工改表，用带锁脚本认领，再动手：
   ```bash
   ./scripts/update-status.sh <题目编号> <环境ID> 已认领
   ```
   脚本会用文件锁重新读最新清单、校验状态、自动填北京时间，两个人同时认领同一题时只有一个能成功，另一个会报错退出。
   状态改动一律走这个脚本，不要两个人同时手工改同一个表。

4. 进 tmux 再解题，一题一会话，所有操作都在 tmux 里：
   ```bash
   ./scripts/start-tmux.sh <环境ID> <题目编号>
   tmux attach -t ctf-<环境ID>-<题目编号>
   ```
   每道题独立会话、独立日志文件，互不干扰。会话内子任务分屏用 `log-window.sh` 开日志。
   在会话里新开窗口后，必须给新窗口开日志，否则该窗口不记日志：
   ```bash
   ./scripts/log-window.sh ctf-<环境ID>-<题目编号> [窗口名]
   ```
   在自己的工作目录里建本题目录，把共享题目附件复制过去再动，不要直接改 `challenges/` 里的原题。
   过程文档放在 `workspaces/<环境ID>/challenges/<题目编号>/过程文档.md`，按 `templates/过程文档模板.md` 写。
   本地要起服务、占端口时，先在 `资源登记.md` 登记，避免并行环境抢同一个端口。

5. 做完登记：先改状态，再记平台提交：
   ```bash
   ./scripts/update-status.sh <题目编号> <环境ID> 已完成 --flag 'flag{...}'
   ```
   flag 只写清单这一处，过程文档里写“flag 见清单对应行”，不要到处贴。
   flag 解出来不等于已提交平台，提交后把清单的“平台提交”列改成 `已提交`，没提交就保持 `未提交`。

## 五、核心铁律（摘要，完整版见《协议与约束.md》）

- 清单先行：没认领不解题，已认领的题别人不碰。
- 工作隔离：只改自己的 `workspaces/<环境ID>/`，不改别人的工作目录，不改共享原题。
- 编号递增：新题编号 = 清单现有最大号 + 1，登记后立即复查，重号时后登记方无条件让位。`CTF-000` 只作格式示例，不计入最大号。
- 冲突不覆盖：本地有改动绝不直接覆盖，冲突存 `.conflict` 副本上报；共享区删了东西，不自动删本地工作副本。
- 日志必开：不在 tmux 外解题，断线用 `tmux attach` 回原会话，不新开同名会话。
- 改完要通知：认领、完成、阻塞、放弃后，在约定的群聊或侧聊发一行：编号 / 状态 / 环境 / 过程文档路径。只改文件不通知，其他环境不会自动知道。
- 放弃要归还：做不下去就把状态改回 `未开始` 或 `已放弃` 并写原因，让别人能接手。

## 六、状态说明

- `未开始`：没人看过，可以分诊。
- `待办`：已分诊，排队等认领。
- `已认领`：已登记认领者，正在准备或刚开始，别人不碰。超 1 小时未动到进行中视为失联，可接管。
- `进行中`：正在解，过程文档已有内容。
- `已完成`：本地已解出，flag 已记清单，过程文档已写完。
- `已放弃`：认领者放弃，已写原因，可重新认领。
- `阻塞`：卡住了，已写阻塞原因和需要的帮助。

平台提交是另一列，和“已完成”分开：`未提交` / `已提交`。

## 七、适用范围和红线

- 本模板 v1 只保证同一台主机、同一文件系统下的多环境并行。跨主机的环境不能直接共用这套文件，需要另外的私有同步通道，公开模板仓不负责同步实战数据。
- 只打 CTF 给的目标，不打 CTF 平台本身、其他选手、真实网站。
- flag、目标地址、凭据只放本地实战实例，不推公开仓库，不发公开群聊。
- 付款、发布、删除他人文件、扩大权限这类操作，仍需用户或题目负责人批准，不在这套框架里默认授权。
- Kali 系统时间是 -04:00，和北京时间差 12 小时，清单时间统一写北京时间。`update-status.sh` 会自动按北京时间填写，手工改表时也要按这个口径。
