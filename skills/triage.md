# Triage · 总入口与通用解题循环

> 适用题型：拿到一道题还不知道是哪类时，先读这个。分诊定题型，再去读对应的 skill。
> 前置：会用 `file`、`nmap` 基础参数，知道 flag 长什么样（`flag{...}` 类格式）。

## 前置工具（Prerequisites）

- `file` / `binwalk` / `strings`：附件与二进制初判三件套（`apt install file binwalk binutils`）。
- `nmap` / `whatweb`：Web 目标初判（`apt install nmap whatweb`）。
- `checksec`：二进制保护初判（pwntools 自带或 `apt install checksec`）。
- 都是现成小工具，赛前装好；赛中缺啥装啥。（人工/联网场景口径；Agent/断网/防污染场景走 `prompts/ctf-solve.md`「三、工具边界」，不许安装）

## 触发词

- "这道题是哪类""先看什么""分诊"、拿到附件/URL 还没定题型时
- "卡住了""10 分钟没思路""换个方向"

## 能力边界

- 不讲具体题型的技术细节 → 分诊定题型后，去对应题型 skill 按清单走。
- 不写 Writeup 正文 → flag 到手后去 `writeup.md`。
- **模型分档**：本文件是「人用总入口」（云端大模型 / 人工解题）；本地小模型 Agent 解题走 `prompts/ctf-solve.md`（瘦身规范：只规定目录、工具边界、停机闸门，不读题型 skill）。

## 解题检查清单（按顺序走，一个 OODA 循环）

1. **设定起点与目标（Origin/Goal）**：写下来——起点是什么（URL/附件/二进制）、目标是什么（flag 格式、提交方式）。没写下来就别动手。
- **工作目录隔离**：先把题目附件拷贝到 `{{workspace}}/{{category}}/{{slug}}/` 再动手，原题目录保持只读不碰（防污染 + 随时可回退重来）。
2. **确定性侦察（第一轮必须是这个，零思考成本）**：
   - 有 URL → `nmap` 看端口 + `whatweb` 看指纹 + 扫目录（见 `web.md` 第 1 步）。
   - 有附件 → `file` + `binwalk -e` + `strings | grep -i flag`。
   - 有二进制 → `file` + `checksec` + `strings`。
   - 侦察结果先记下来再分析，不许边扫边猜。
3. **分诊**：按上表定题型，认领对应 skill。10 分钟没思路 → 回到本文件重走一遍分诊（题型误判是头号时间黑洞）。
4. **执行 skill**：按对应 skill 的检查清单一步步走，每做一步记一条：
   - **Fact**：确认了的客观发现（如"SQL 报错注入点在 id 参数"）。
   - **Intent**：下一步要试的方向（如"试时间盲注"）。
   - **DeadEnd**：证实走不通的路 + 原因（如"WAF 拦 union，换报错注入"）。
   - 记在哪：过程文档.md（"已排除路径"一节）；模板仓里只记方法，不记具体题。
- **什么算「新 Fact」（三否定判定）**：以下三种**不算**进展，不计入「连续 3 轮无新 Fact」的轮数——
1. 命令报错了，但报错原因没弄清（只记了报错、没记原因）；
2. 同一条命令换个参数再跑一遍（背后没有新假设）；
3. 把工具输出原样贴进笔记，没有提炼出结论。
只有「经验证的新结论」（如「确认 SQL 报错注入点在 id 参数」）才算一个 Fact。每轮实验前先写清「验证哪个假设、什么结果否定它」，跑完对照：证实或证伪了才算一轮有效进展。
5. **停机闸门（硬规则：连续 3 轮无新 Fact 立刻停机，不许自己续）**：
   1. 停下，不许继续调参重试。
   2. 重读已记的 Fact + DeadEnd，找没试过的分叉。
   3. 查 `patterns.md` 有没有匹配当前特征的模式。
   4. 搜同类题解（关键词：题型 + 关键特征，如 "pwn tcache uaf writeup"）。
   5. 还卡住 → **强制停机**：① 按下方「状态卡」格式输出当前状态并写入外部表；② 标记 DeadEnd；③ **停下等用户给出下一步提示**——拿到提示前不许自己换方向继续试。用户可选择给提示，或指示先放下换题（换题也必须先输出状态卡）。

**状态卡格式**（停机时输出；多环境/多 agent 共享事实源）：
- category：题型（如 pwn）
- flag：已知/部分 flag 信息（无则写「未得」）
- hypothesis：当前主假设 + 什么结果能证伪它
- facts：已证实的事实，一行一条
- next：停机时只写「等用户下一步提示」
6. **收尾**：flag 到手后先过「解出三条件」，通过再按 `writeup.md` 记 Writeup；把过程中发现的新模式/新坑回填到对应 skill（见《使用与协同评估.md》新增流程）。
- **解出三条件**（缺一不可）：① flag 字符串来自程序输出、远程返回或题面规定的结果（不是猜的、凑的）；② 工作目录里有一条能再次得到它的命令或脚本（复现链超两三步就写成 `solve.py`/`solve.sh`）；③ 题面规定了格式时，flag 与格式一致。
> **防幻觉铁律**：数字、偏移、密钥、地址、flag 只写工具输出或文件里实际出现的值。

## 状态外置（多环境共享事实源）

- Fact / Intent / DeadEnd **必须写进外部表**（过程文档.md"已排除路径"一节，或 notes.md），不靠 agent 的记忆——上下文一切换，记忆就丢。
- 多环境 / 多 agent 并行解题时，这张外部状态表就是共享事实源：谁认领了哪道题、哪条路已证实走不通，都以表为准，不口头传、不靠猜。
- 模板仓的 skills/ 里只沉淀通用方法，不记具体题目的状态（见《协议与约束.md》第 8 条）。

## 常用工具

| 工具 | 用来干什么 | 一句话用法 |
| --- | --- | --- |
| file / strings -a -n 6 / 关键词搜 | 开场三板斧 | 列文件/大小/file 类型→二进制跑 `strings -a -n 6`→文本搜 `flag{`/ctf{/FLAG{/key/password；候选 flag 先核对题面格式（文章 §5）；binwalk 另用于固件/附加文件分离 |
| nmap / whatweb | Web 目标初判 | 端口 + 指纹，决定深挖哪 |
| checksec | 二进制保护初判 | pwn/reverse 分流依据 |
| 解题 Agent（如 Pi Agent） | 主力交互式解题 | 文章作者用 Pi Agent 四并发；选型要点：「快速交互>强推理」（除 Crypto 外），安装方式原文未给、需手动（文章 §3§4） |
> **工具边界**（文章 §5）：默认比赛机断网——只用已装好的工具，不许 `pip install`/`apt`/`brew`；按「本机 → `ssh ubuntu` → `ssh kali`」顺序找，三处都没有就停下来问用户。

## 常见坑

- 坑 1：跳过第 2 步直接开干 → 侦察 5 分钟能省 1 小时弯路，永远先侦察。
- 坑 2：题型定错了死磕 → 特征对不上清单就回分诊表重判，别"感觉像 Web"。
- 坑 3：DeadEnd 不记 → 同一个坑踩两遍。证实走不通的路必须写下来。
- 坑 4：一个人闷头卡 1 小时 → 连续 3 轮无新 Fact 立刻按第 5 步停机闸门走：输出状态卡、等用户下一步提示，不许自己闷头续。
